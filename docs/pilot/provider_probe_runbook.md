# FLASHIN — provider probe runbook

## Назначение

Строгая проверка внешних интеграций является частью `make pilot-gate`. Пилот не получает решение **GO**, если хотя бы один обязательный provider probe завершился ошибкой, отключён или не подтверждает наличие рабочих production-данных.

Проверки запускаются внутри работающего контейнера `backend`, поэтому используют тот же production `.env`, сетевой контур и зависимости, что и приложение.

## Что проверяется

1. **Telegram** — read-only вызов Bot API `getMe`; подтверждает, что токен принадлежит доступному боту.
2. **YooKassa** — создание тестового платежа на **1,00 RUB**; подтверждает shop ID, secret key, return URL и возможность создавать платежи. Проверка создаёт реальную тестовую сущность у провайдера, но не подтверждает успешную оплату клиентом и обработку webhook — это проверяется в 20-заказном пилоте.
3. **MoySklad** — read-only запрос товарного каталога; подтверждает авторизацию и требует, чтобы каталог содержал хотя бы один товар.
4. **R2/S3** — запись, чтение и удаление временного объекта; требуется production-хранилище `MEDIA_STORAGE=r2|s3`.
5. **Meilisearch** — `/health` и статистика индекса товаров; сервис должен быть доступен, а индекс — непустым.

## Команды

```bash
# Строгая проверка. Используется по умолчанию и блокирует запуск при любой ошибке.
make check-integrations

# Полный live gate: публичные URL, readiness, каталог, security headers и provider probes.
make pilot-gate

# Диагностический режим без блокировки — только для настройки, не для допуска пилота.
python3 scripts/check_integrations.py --advisory

# Запуск probes на host Python вместо backend-контейнера — только для диагностики.
python3 scripts/check_integrations.py --host-python --advisory

# Показать детальный вывод. Не копировать его в публичные issue/PR/чаты.
python3 scripts/check_integrations.py --verbose
```

По умолчанию консоль получает только безопасную сводку без provider IDs и confirmation URL. Детальный отчёт сохраняется локально:

- `docs/pilot/integration_check_report.json`
- `docs/pilot/integration_check_report.md`

Live readiness-отчёты также остаются локальными. Все эти файлы исключены из Git, поскольку могут содержать реальные операционные идентификаторы.

## Решение

- **GO** — все пять probes завершены успешно.
- **NO-GO** — отсутствует credential, контейнер не запущен, внешний API недоступен, R2/S3 не выполняет полный write/read/delete, MoySklad пуст, Meilisearch выключен/пуст либо YooKassa не создаёт тестовый платёж.

Provider probes подтверждают доступность и базовую работоспособность интеграций, но не заменяют сквозные сценарии оплаты, webhook idempotency, движения остатков, возвратов и reconciliation первых 20 заказов.

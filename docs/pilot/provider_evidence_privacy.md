# Provider evidence privacy — pilot v26

This policy applies to live provider probes and the signed evidence generated by `scripts/check_integrations.py`. It hardens the evidence boundary without changing the Telegram → YooKassa → order → stock/MoySklad → fulfillment → refund → notification business lifecycle.

## Principle

Signed pilot evidence must prove readiness without becoming a second store of provider credentials or operational identifiers. Provider probes therefore emit only bounded failure categories and the minimum non-identifying success signals needed for admission.

Never persist in probe stdout/stderr or signed evidence:

- Telegram bot tokens, raw `initData`, token-bearing Bot API URLs, bot IDs or usernames;
- YooKassa secret keys, Basic authorization values, provider error bodies, payment IDs, confirmation URLs or arbitrary provider values;
- MoySklad credentials, configured entity UUIDs, provider response bodies, external document IDs or target URLs;
- Meilisearch master keys, private service URLs or index names;
- R2/S3 access keys, secret keys, bucket names, provider exception bodies or tracebacks;
- raw exception messages that can contain any of the above.

## Probe behavior

- Telegram `getMe` remains read-only. Success records only that the provider identity was verified. HTTP/network failures record only a bounded status code or exception class.
- YooKassa still creates one idempotent 1.00 RUB pilot test payment per release/return-URL scope and therefore still requires `--acknowledge-side-effects`. Success records only bounded status/amount/currency/confirmation-required fields; provider payment and confirmation identifiers are omitted.
- MoySklad remains a required GET-only readiness probe for catalog plus the configured organization, counterparty, store and delivery service. Configured UUIDs are never emitted.
- R2/S3 runs only when durable object storage is enabled. Its preflight performs write → read → delete and attempts cleanup even after a read failure. Provider exception details are suppressed.
- Meilisearch runs only when search is enabled. Success records only that documents are present and whether indexing is active; private URL/index names are omitted.

## Defense in depth in the evidence runner

The aggregator still redacts captured stdout/stderr before signing. v26 expands redaction beyond literal secret values to include URL-encoded secret forms, Telegram token-bearing Bot API URLs, YooKassa Basic credentials, and MoySklad Basic credentials. If the subprocess runner itself fails, signed evidence records only the exception class rather than `str(exception)`.

Probe-local bounded output is the first safety layer. Aggregator redaction is a second layer, not a substitute for safe probe behavior.

## Validation

`backend/tests/test_provider_probe_privacy.py` injects deliberately sensitive values into simulated Telegram, YooKassa, Meilisearch, R2/S3 and subprocess failures and fails if those values reach evidence output. CI evidence proves the privacy controls in code only; it is not live-provider proof.

## Live pilot evidence

A real-money pilot remains fail-closed until the exact deployed immutable release produces fresh signed provider evidence, public HTTPS readiness is verified, P01–P20 is completed from deployed observations, governance evidence is valid, and final admission returns `go: true`.

Generate a fresh signed provider report only on the intended deployed release:

```bash
python scripts/check_integrations.py run --acknowledge-side-effects
```

Do not copy raw provider dashboards, credentials, token-bearing URLs, webhook bodies or provider response bodies into `docs/pilot/evidence`.
